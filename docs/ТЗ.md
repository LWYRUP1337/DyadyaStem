## 1. Общие договорённости!!!

### 1.1. Адреса и окружение

| Что | Значение |
| --- | --- |
| Фронтенд | `http://localhost:5173` |
| API | `http://localhost:8000`, **без префикса** (`/auth/login`, `/projects`, ровно как в контракте) |
| Swagger | `http://localhost:8000/docs` |
| Garage s3 | API `:3900` |
| Postgres / Redis |  `5433` (внешний)/ `5432`(внутренний) / `6379` |
| Адрес API для фронта | переменная `VITE_API_URL` |

Всё поднимается командой `docker compose up --build` из корня. Секреты только в `.env`, в git лежит `.env.example`.

### 1.2. Форматы данных

- JSON в `snake_case`, id — UUID строкой, время — ISO 8601 UTC с `Z`, длительности и точки лупа — секунды (float).
- Темп везде `tempo_ratio` (`1.0` = 100%). Проценты только в `speed_ramp_config` и в xlsx-экспорте.
- Ошибки: `{ "detail": "..." }`. Чужой или несуществующий ресурс — `404`.
- Состояние микшера `stem_volumes` — объект по типу стема, всегда целиком (формат в контракте).

### 1.3. Хранилище

- Бакет `dyadyastem`.
- Исходник: `sources/{project_id}.mp3`.
- Стемы: `stems/{project_id}/{stem_type}.mp3`, **mp3 320 kbps, стерео, 44.1 кГц**. ML-Ops подтверждает формат замером до 10/16, после этого смена формата только через PR.
- Ссылки на стемы — presigned URL со сроком жизни 1 час, подписанные публичным адресом (MINIO_PUBLIC_ENDPOINT), а не garage:3900.
- У Garage настроен CORS для http://localhost:5173 (параметр CORS_ORIGINS в init_garage.py / docker-compose.yml). Без этого браузер не загрузит дорожки, даже с правильной ссылкой. Настраивает ML-Ops.
- Файлы `*.mp3` и `*.wav` в git не коммитятся (они в `.gitignore`); тестовые стемы передаются через общую папку.

### 1.4. Контракт бэкенд ↔ воркер

- Бэкенд ставит задачу **по имени**: `celery_app.send_task("process_audio", args=[project_id])`. Код воркера в бэкенд не импортируется.
- Статусы проекта: `processing` → `ready` или `error`. Бэкенд ставит `processing` при создании и при повторе (и очищает `error_message`). Воркер ставит `ready` или `error`.
- Воркер сам пишет в Postgres: `tracks`, `duration_sec`, `status`, `error_message`. Задача идемпотентна: перед повторной обработкой удаляет старые строки `tracks` и файлы стемов проекта.
- Текст `error_message` пишется для пользователя, по-русски и по делу («Не удалось скачать файл по ссылке: файл больше 25 МБ»).

### 1.5. Сохранение состояния workspace

Debounce 1.5–2 с на изменения. При уходе со страницы (`visibilitychange`, `pagehide`) — немедленный `fetch` с `keepalive: true`. Копия состояния в `localStorage`. **`sendBeacon` не используем:** он умеет только POST и не передаёт заголовок `Authorization`.

### 1.6. Обработка ошибок на фронте

| Ответ | Что делает интерфейс |
| --- | --- |
| `401` | очищает токен, переходит на экран входа |
| `404` | сообщение «не найдено», возврат на главную |
| `409 too_many_processing` | «Слишком много проектов в обработке (максимум 10)» |
| `413` | «Файл больше 25 МБ или длиннее 10 минут» |
| `422` | показывает ошибку у соответствующего поля |
| сеть / `5xx` | общий тост «Что-то пошло не так, попробуйте ещё раз» |

### 1.7. Зоны владения папок

| Папка | Владелец |
| --- | --- |
| `backend/`, миграции, `docs/openapi.json` | Бэкенд |
| `worker/`, `docker-compose.yml`, `.env.example`, `README.md`, CI, `docs/` (кроме контракта) | ML-Ops |
| `frontend/` каркас, `src/pages/Auth`, `src/pages/Dashboard`, `src/components/common`, `src/components/dashboard`, `src/components/fragments`, `src/api/{auth,projects,fragments,export}.ts`, `src/types` | Фронт 1 |
| `frontend/src/pages/Workspace`, `src/audio`, `src/components/player`, `src/api/state.ts` | Фронт 2 |

В чужую папку правки идут только через PR с ревью владельца.

### 1.8. Как работаем

- **Ветки:** `feature/<имя>`, `fix/<имя>`. В `main` только через Pull Request, минимум один ревьюер из смежной роли (бэкенд ↔ фронт, ML-Ops ↔ бэкенд, Фронт 1 ↔ Фронт 2).
- **Изменение контракта или схемы БД:** PR, который правит `docs/api-contract.md` (и DBML), согласуют и тот, кто отдаёт данные, и тот, кто их потребляет. Сообщение в общий чат. Код и контракт меняются в одном PR. С 12/11 (фича-фриз) контракт не меняется.
- **Моки:** пока API не готов, фронт работает на заглушках по примерам из контракта. Переключатель `VITE_USE_MOCKS`. Мок должен возвращать ровно ту форму, что описана в контракте.
- **OpenAPI:** в конце каждого спринта Бэкенд кладёт `docs/openapi.json`. Фронты сверяют свои типы с ним.
- **Готово** значит: код в `main`, работает в `docker compose`, соответствует контракту, у задачи выполнено её «Готово, когда».

Список дорожек динамический: 4 или 6. Готово, когда: экран совпадает с макетом, оверлеи открываются и закрываются.

**Спринт 2 (10/19 – 10/30)**

- **Ф2-2.1** — Аудио-движок в `src/audio` (обычные классы TypeScript, без React): загрузка стемов по URL (`fetch` + `decodeAudioData`) из тестовой папки, один общий `AudioContext`, синхронный старт и пауза всех дорожек, `GainNode` на дорожку и общий, mute и solo, позиция и перемотка. Готово, когда: 4 дорожки играют синхронно (на трёх минутах дрейф не слышен), громкость и mute дорожек не сбиваются от общей громкости.

**Спринт 3 (11/02 – 11/13)**

- **Ф2-3.1** (11/02 – 11/06) — Waveform: пики считаются один раз из `AudioBuffer`, отрисовка на canvas, курсор, перемотка кликом. Готово, когда: waveform совпадает со звуком на тестовых стемах.
- **Ф2-3.2** (11/09 – 11/13) — A/B-луп: включение режима, точки A и B на таймлайне, минимум 1 с, пересечение невозможно, зацикливание без щелчков. Готово, когда: на тестовых стемах отрезок крутится без слышимых артефактов на стыке.

**Спринт 4 (11/16 – 11/27)**

- **Ф2-4.1** (11/16 – 11/20) — Попап «bpm»: смена скорости без смены высоты звука (SoundTouch через AudioWorklet), слайдер, сброс к 100%. Готово, когда: на скорости 70% и 130% звук не меняет высоту.
- **Ф2-4.2** (11/16 – 11/27) — Workspace через API: `GET /projects/{id}` (при ошибке загрузки по presigned URL — повторный запрос проекта за свежей ссылкой), `GET/PATCH /state`, автосохранение по разделу 1.5, восстановление состояния при открытии. Готово, когда: после перезагрузки страницы громкости, mute, точки лупа и скорость возвращаются; **MVP 11/27**.

**Спринт 5 (11/30 – 12/11)**

- **Ф2-5.1** (11/30 – 12/07) — Speed Ramp: попап с тремя элементами и жёсткими границами (повторы 1–10, шаг 2–25%, потолок 100–150%), кнопка «ОК», счётчик повторов, шаг, потолок, **смена скорости только на границе повтора**. Готово, когда: скорость растёт каждые N повторов и останавливается на потолке, значения не выходят за границы.
- **Ф2-5.2** (12/08 – 12/11) — Фрагменты: «Сохранить фрагмент» (`POST`, имя «Новый фрагмент», «Новый фрагмент 2» и т. д.), открытие фрагмента (`GET` → применить состояние → `PATCH /state` с `active_fragment_id`), автосохранение в активный фрагмент, шлифовка звука, проверка в Chrome, Firefox, Safari. Использует `api/fragments.ts` от Фронта 1. Готово, когда: фрагмент сохраняет и восстанавливает громкость, скорость, Speed Ramp и точки лупа, прогресс продолжается с последней скорости.

**Спринт 6** — багфиксы, участие в репетиции.
